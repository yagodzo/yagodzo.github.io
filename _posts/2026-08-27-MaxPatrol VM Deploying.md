# MaxPatrol VM

MaxPatrol VM — флагманский сканер уязвимостей на платформе MaxPatrol 10 (Windows/Debian). **Ключевые функции:** инвентаризация и классификация активов, построение топологии в реальном времени, поиск уязвимостей без повторного сетевого сканирования (за счет агентского метода), автоматизация и контроль процессов патч-менеджмента.
## Архитектура

Система состоит из пяти компонентов:

- **Core** — управляющий сервер. Централизованное управление, хранение конфигураций, расчет рисков, веб-интерфейс.
- **Agent** — компонент сканирования (аутентифицированный/неаутентифицированный). Собирает данные об ОС, ПО, железе и учетных записях, передавая их в Core.
- **Knowledge Base** — единая база знаний (сигнатуры уязвимостей, бюллетени, рекомендации) для всех продуктов PT.
- **PT MC** — сервис администрирования. SSO, управление доступом (RBAC), аудит действий.
- **PT UCS** — сервис обновлений. Доставка новых версий и баз уязвимостей через SaltStack.

## Лицензирование

- **Базовая:** ограничивает максимальное количество узлов (любые устройства с IP-адресом, включая ВМ любой вложенности).
- **Инфраструктурная:** покрывает использование серверных компонентов и агентов.

# Развертывание MaxPatrol VM
## Системные требования

**Сервер основных компонентов (Core, MC, KB, UCS):**

- **CPU**: 2.2 ГГц, суммарно 32 логических ядра (при включенном Hyper-Threading можно вдвое меньше).
- **RAM**: 64 ГБ.
- **Disk**: от 400 ГБ (рекомендуется 4 диска по 1200 ГБ, 10k RPM или эквивалентные SSD).
- **Network**: 2 интерфейса по 1 Гбит/с.

**Сервер агента/коллектора (MP 10 Collector):**

- **CPU**: 2.2 ГГц, 4–8 логических ядер (4 ядра до 4 потоков сканирования, 8 ядер до 20 потоков).
- **RAM**: 4–12 ГБ (пропорционально нагрузке).
- **Disk**: 300 ГБ.
- **Network**: 1 интерфейс 1 Гбит/с.

**Поддерживаемые ОС:**

- **Linux**: Astra Linux SE 1.7.5, Debian 10.3–10.13 (64-bit).
- **Windows**: Server 2012 / 2012 R2 / 2016 / 2019 / 2022 (только для агентов/коллекторов).

## Подготовка виртуальной среды

- Зарезервировать весь объем RAM гостевой ОС (Reserve all guest memory / All locked).
- Дисковая подсистема: Thick Provision Eager Zeroed, режим Independent + Persistent.
- Сеть: При NAT использовать FQDN вместо IP, обеспечить разрешение имен через DNS.
- Linux: Обновить репозитории (`apt update && apt upgrade`), установить `openssh-server`, `net-tools`.
## Порядок развертывания

Управление установкой: роль Deployer (SaltStack: Master на сервере развертывания, Minion на целевых узлах).  
**Строгий порядок установки:**

1. Deployer
2. PT MC (включая SqlStorage)
3. Knowledge Base
4. RMQ Message Bus
5. Core
6. Активация лицензии
7. MP 10 Agent (Collector)
8. PT UCS

_Примечание_: PT UCS и Deployer размещать на одном сервере.

## Алгоритм установки ролей (Linux)

1. Распаковать архив: `tar -xf <имя_архива>.tar.gz`
2. Запустить скрипт: `<папка>/install.sh`
3. Принять лицензию (I Accept).
4. Выбрать: _Create New Application_ (для первого компонента группы) или существующее.
5. Выбрать: _Deploy New Instance_ → _Basic configuration_.
6. Указать `HostAddress` (IP или FQDN).

**Параметры конфигурации (Basic configuration):**

- **SqlStorage**: Приложение `Management and Configuration`. Параметр: `HostAddress`.
- **Management and Configuration**: Параметры `HostAddress`, `PostgreHost`, `DefaultLocale`.
- **Knowledge Base**: Параметры `HostAddress`, `PostgreHost`, `MCAddress` (порт 3334), `CoreAddress` (порт 443), `DefaultLocale`.
- **RMQ Message Bus**: Приложение `MaxPatrol 10`. Параметр: `HostAddress`.
- **Core**: Приложение `MaxPatrol 10`. Параметры `HostAddress`, `MCAddress` (3334), `KBAddress` (8091), `PostgreHost`, `RMQHost`, `DefaultLocale`.

**Важно**: После установки Deployer скопировать `/opt/deployer/pki/CAbundle.crt` на сервер Core и выполнить:  
`rabbitmqcfg set -p CACertFile <путь_к_файлу> -v`

## Активация лицензии (онлайн)

1. Поместить файлы лицензии (`.grdvd` и `.txt`) в каталог:  
    `/var/lib/deployed-roles/<Приложение>/<Экземпляр_Core>/data/licensing`
2. Выполнить активацию (от root):  
    `docker exec -it $(docker ps | awk '/licensing/ {print $NF}') /usr/local/bin/guardantutils/grdspactivation /var/lib/microservice/<файл>.grdvd /serialfile=/var/lib/microservice/<файл>.txt`
3. Перезапустить сервисы:  
    `docker restart $(docker ps | awk '/core-|kb-/ {print $NF}')`
4. Проверка: Веб-интерфейс → Система → Управление системой → О системе.

## Установка MP 10 Agent (Windows)

1. Запустить `MPXAgentSetup_<версия>.exe`, принять лицензию, указать пути.
2. Задать «Имя агента» и «Адрес обработчика данных» (IP/FQDN сервера Core).
3. Настройка доверия на сервере Deployer:

```bash
   cp /opt/deployer/pki/legacy_ca/windows-selfsigned-default.pem /opt/deployer/pki/trusted_ca/
   dpkg-reconfigure deployer
   /opt/deployer/bin/Restart-Configuration.ps1 -RoleTypeId RmqMessageBus
```

4. Проверка: Веб-интерфейс → Система → Управление системой → Агенты.

## Установка PT UCS

1. Распаковать архив UCS, запустить `install.sh`.
2. В окне конфигурации выбрать **Skip**.
3. Проверка подписки: `salt-key -L` (имя сервера должно быть в _Accepted Keys_).

# Обзор веб-интерфейса MaxPatrol VM

## Management and Configuration (MC)

Единая среда аутентификации и управления доступом.

- **Пользователи:** Настройка LDAP, синхронизация прав с группами Active Directory.
- **Роли:** Клонирование и адаптация базовых ролей. Ограничение доступа к объектам инфраструктуры настраивается в MaxPatrol 10 (Система -> Права доступа).
- **Журнал действий:** Аудит действий пользователей.

## MaxPatrol 10 Core

Основной управляющий сервер (95% времени работы). Обеспечивает централизованное хранение конфигураций, управление компонентами, автоматизацию процессов и работу веб-интерфейса.

## Дашборды и виджеты

- **Виджет:** Графический элемент представления данных (гистограмма, таблица).
- **Дашборд:** Страница, содержащая набор виджетов.
- **Возможности:** Создание из шаблонов, кастомизация состава и расположения, сохранение в PNG, детализация данных по клику, создание собственных виджетов на базе PDQL-запросов.

## Активы и PDQL

- **Группы активов:**
    - _Статические:_ ручное наполнение или включение вложенных динамических групп.
    - _Динамические:_ автоматическое наполнение по заданным фильтрам.
- **PDQL-запросы:** Язык фильтрации базы активов. Поддерживает группировку, сортировку, агрегацию. Применяется ко всей базе или к выбранной группе активов. Сохраняется в библиотеку или конвертируется в виджет/отчет.
- **Карточка актива:** Полная конфигурация, уязвимости, история изменений, метрики CVSS. Позволяет строить фильтры по параметрам актива и сравнивать конфигурации во времени.
- **Паспорт уязвимости:** Список затронутых активов и групп, детальное описание уязвимости и рекомендации по устранению.

## Сбор данных

- **Справочники:** Шаблоны для подбора учетных записей (стандартные и пользовательские).
- **Учетные записи:** Хранилище логинов/паролей и сертификатов для сканирования в режиме Audit (аутентифицированное).
- **Профили:** Шаблоны настроек модулей сбора данных. Стандартные (только чтение) служат базой для создания пользовательских.
- **Задачи:** Определение целей (IP-адреса, группы активов), выбор профиля, запуск вручную или по расписанию. Система автоматически генерирует подзадачи для агентов.

## Система

- **Отчеты:** Формирование через отдельные задания. Рекомендуется создавать пользовательские шаблоны на базе стандартных.
- **Уведомления:** Гибкая настройка оповещений о любых событиях в системе.
- **Политики:** Формализация процессов устранения уязвимостей:
    1. _Значимость активов:_ Приоритизация закрытия уязвимостей по критичности актива.
    2. _Сроки актуальности:_ Контроль регулярности сканирований Pentest и Audit, предотвращение выпадения активов из цикла.
    3. _Статусы уязвимостей:_ Категоризация и контроль договоренностей с IT-подразделениями.
    4. _Отметка «Важное»:_ Выделение критичных уязвимостей для первоочередного устранения.

## Управление системой

- **Мониторинг:** Состояние компонентов, лицензий, агентов, базы знаний и очередей обработки активов.
- **Настройка системы:** Базовые проверки для первичного ввода продукта в эксплуатацию.

# Методы и модули сканирования MaxPatrol VM

## Общие требования

Обеспечить сетевую доступность целевых хостов для агентов сканирования. Настроить правила на межсетевых экранах и СЗИ для предотвращения блокировки трафика.

## Обнаружение хостов (Host Discovery)

Используются ICMP ping, TCP ping или оба метода.

- **HostDiscovery**: Базовый поиск. TCP (часто используемые порты) или ICMP.
- **Inventory Profile**: Поиск с определением ОС и типа узла. TCP или ICMP.
- **Os Detection Profile**: Определение ОС. Только TCP. Требуется минимум один открытый и один закрытый порт.
- **PortScan Full Range**: Полный перебор всех TCP-портов (1–65535).

## Модуль Pentest (Метод «черного ящика»)

Сканирование без использования учетных записей. Выявление открытых портов, сервисов и уязвимостей сетевого уровня.

- **Профили**: `Bruteforce`, `Fast/Full/Safe/Unsafe PenTest`, `Database`, `HTTP/Mail/Remote Management/SAP/Service/SNMP/Windows Discovery`.
- **Настройка**: Определение портов -> список UDP-служб -> проверки уязвимостей. Для брутфорса используются стандартные словари логинов/паролей.
- **Важно**: Система автоматически исключает сетевые принтеры из сканирования. Не отключать данную опцию.

## Модуль Audit (Метод «белого ящика»)

Сканирование с использованием учетных записей. Сбор полной инвентаризационной информации (ОС, ПО, патчи, конфигурации). Учетная запись должна обладать правами, необходимыми для чтения данных на целевом хосте.

**Стандартные профили и особенности настройки:**

- **Windows**: `Windows Audit`, `Vulnerabilities/Updates Discovery`, `DC Audit`. _Требование_: При наличии Kaspersky Endpoint Security добавить запуск PowerShell через WMI в исключения правила адаптивного контроля аномалий (ACA).
- **Active Directory**: `MS AD Audit`, `Windows DC Audit`. _Требование_: Для просмотра результатов создать динамическую группу активов по условию `ActiveDirectory`.
- **Unix**: `Unix Audit`. _Требование_: Ядро Linux > 2.6.38, утилита `dmidecode` > 2.8.
- **Сетевые устройства**: `SNMP Network Device`, `SSH Network Device`, `SSH Cisco (Enable Mode)`. _Требование_: Для Cisco в режиме Enable использовать учетную запись типа «пароль» для повышения привилегий.
- **СУБД**: `MSSQL Audit`, `Oracle Audit`. _Требование_: Для Oracle очищать таблицу `SYS.AUD$` (пространство SYSTEM) не реже раза в 3 месяца.
- **Виртуализация и Web API**: `vSphere Audit`, `Web API Audit` (Check Point, TeamCity, Artifactory, Zabbix).
- **Check Point**: `Management Server SSH`, `OPSEC`.

**Конфигурация**: Параметры модуля задаются при создании пользовательского профиля на базе стандартного или непосредственно в задаче на сбор данных.
